# Real-data training runbook

This runbook is a staged procedure, not evidence that training has already run. The GitHub CI environment only runs small synthetic unit tests; do not train a research model inside CI.

## 0. Verify your data and environment

Use a machine with enough RAM, disk, and preferably a CUDA-capable GPU. Activate the project's Python 3.10/3.11 environment and install the project plus development dependencies:

```powershell
python -m pip install -e ".[dev]"
python -c "import torch; print('torch', torch.__version__, 'cuda available:', torch.cuda.is_available()); print('gpu:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

Check that preprocessed inspiratory NIfTI volumes and corresponding masks are present. The pipeline expects:
- volumes: `data/processed/nifti/*_insp.nii.gz`
- masks: `data/processed/masks/*_insp_mask.nii.gz`

Do not proceed if masks are empty, misaligned, or generated by a fallback that has not been QC'd. Five-lobe features remain disabled in the current patch extraction path because a validated five-label mask is not connected.

## 1. Extract real patches

Use a **new, empty output directory** for each extraction attempt. Existing manifests are deliberately not overwritten, to avoid stale shard mixing.

```powershell
python scripts/make_patches.py --nifti-dir data/processed/nifti --masks-dir data/processed/masks --output-dir data/processed/patches_run1 --patch-size 50 --max-patches 100 --shard-size 1000
```

Confirm that the command reports a nonzero number of patches and creates `patch_manifest.parquet` plus the referenced shard files. Inspect patient IDs, patch counts per scan, lung fractions, LAA-950 fractions, and the one-/two-channel distribution before training. The current loader uses all available patches; define patient-level train/validation/test separation before any claim of held-out performance.

## 2. Train the encoder

The command below is a real-data run, not `--dry-run`. Start with a small smoke run only after patch QC, then start the intended long training job. For a long run, choose the total epoch count up front and keep that same target when resuming.

```powershell
python scripts/train_encoder.py --shards-dir data/processed/patches_run1 --checkpoint-dir outputs/real/checkpoints --epochs 30 --batch-size 4 --lr 0.0001 --temperature 0.07 --device auto
```

The script writes:
- `outputs/real/checkpoints/encoder_best.pt` — best epoch by training contrastive loss
- `outputs/real/checkpoints/encoder_latest.pt` — latest epoch, optimizer/scheduler state, and history for resuming
- `outputs/real/checkpoints/training_history.csv` — per-epoch loss and batch count

If interrupted, resume with the **same total epoch count and settings**:

```powershell
python scripts/train_encoder.py --shards-dir data/processed/patches_run1 --checkpoint-dir outputs/real/checkpoints --epochs 30 --batch-size 4 --lr 0.0001 --temperature 0.07 --device auto --resume-from outputs/real/checkpoints/encoder_latest.pt
```

Use `--device cuda` only when CUDA is available. Reduce batch size if GPU memory is insufficient; keep batch size at least 2 for NT-Xent. If using a two-channel inhale/registered-exhale patch set, the encoder detects the channel count from the dataset. Verify registration quality before using paired-phase patches.

## 3. Fit the density model

Run this only after real encoder training completes and eligible normal patches are defined:

```powershell
python scripts/fit_density.py --shards-dir data/processed/patches_run1 --encoder-ckpt outputs/real/checkpoints/encoder_best.pt --output-model outputs/real/checkpoints/density_model.joblib --model-type gmm --components 8
```

The current normal-patch filter uses `LAA-950 <= 0.01`; this is a heuristic, not equivalent to the full CT-RATE report-negative normality definition described in the project plan. Document this limitation and verify the number and patient IDs of selected patches. Fit only on the training partition.

## 4. Current pipeline boundary

Real patient-level scoring and held-out proxy evaluation are **not implemented end-to-end yet**. The scoring script intentionally fails instead of writing an empty or fabricated real report. Do not treat successful encoder training or density fitting as evidence of diagnostic performance. Next work is to implement real patch inference, patient-level aggregation, patient-wise held-out proxy evaluation, and validated lobe mapping. Clinical COPD classification or exacerbation prediction additionally requires real clinical labels/outcomes.

## 5. What to archive for reproducibility

Archive the code commit, data selection/version and access conditions, split manifest, extraction parameters, segmentation and registration QC, environment/package versions, GPU model, seed, training history, best/latest checkpoints, density-fit settings, normal-patch selection counts, and any exclusions. Do not upload gated CT data or model artifacts to a public repository without checking dataset terms.
